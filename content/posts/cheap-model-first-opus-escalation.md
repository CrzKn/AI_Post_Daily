> 核心思路一句话：把「每道题都请最强模型」改成「便宜模型先筛一遍，拿不准的才升级」，判定类任务就能用约四分之一的成本，换来和全程 Opus 基本持平的准确率。

大医院不会让主任医师给每个嗓子疼的人问诊。分诊台先过一遍，多数人当场开药，只有症状可疑的才转给专家。Hacker News 最近一条热帖（https://news.ycombinator.com/item?id=50397429）讨论的，正是把同一套分诊逻辑搬进 LLM 的判定流水线：让一个便宜的小模型先下判断，只把没把握的样本转给 Opus 重判。结果相当干脆——和从头到尾都用 Opus 相比，准确率基本持平，成本只剩四分之一左右。

这条帖子值得写，不是因为又证明了一次「小模型也能用」，而是它把省钱做成了一套可复现的工程动作：怎么定义「拿不准」，直接决定账单与准确率各退让多少。

## 贵的不该花在「送分题」上

这条热帖的场景是高通量判定任务，具体例子是实体消歧：判断一段文本里出现的某个名字，指的到底是哪个实体。这类题量极大、单题不难，但错了要付出代价。

全程用 Opus 当然最稳，可账单里绝大多数钱，都花在了便宜模型本来也能答对的样本上。强模型按 Token 计费，逐样本调用意味着账单随量线性膨胀。便宜模型的边际成本（marginal cost）低得多，天花板也低：碰到罕见写法、歧义重的人名，容易给出一个貌似有理的错误答案。反过来全程用便宜模型，省是省了，却会稳定地错掉一批难例，准确率掉到不可接受。于是真正的问题不是「选哪个模型」，而是「怎么把样本分流」。

## 分流器的结构：判断 + 置信度

级联（cascade）方案只有三步：

1. 便宜模型先对每个样本输出「判断 + 置信度」；
2. 置信度高于阈值的，直接采信；
3. 置信度低于阈值的，走升级（escalation）通道，交给 Opus 重判。

逻辑就这么几行，难点全在阈值——也就是怎么定义「拿不准」。这个旋钮同时管着两个数：漏判率（便宜模型自信地放走的错例）和升级比例（转给 Opus 的样本占比）。阈值松一点，错判就漏下去，准确率往下掉；阈值紧一点，升级比例飙升，账单又回到全用 Opus 的老路。

## 钱到底省在哪

级联的总成本可以拆成两段：没升级的样本按便宜模型单价计，升级的样本按 Opus 单价计。写成式子就是：

- 总成本 = 升级比例 × Opus 单价 + （1 − 升级比例）× 便宜模型单价

便宜模型单价通常比 Opus 低一个数量级甚至更多，所以只要升级比例压得住，总成本就贴着便宜模型那一档。热帖里「只剩四分之一」的结果，意味着绝大多数样本被便宜模型自己消化了，只有少数难例才付 Opus 的钱。省钱的关键从来不是把 Opus 换掉，而是让 Opus 只出现在它真正值得出现的地方。

## 把阈值扫成一条曲线

阈值好不好，别靠感觉，扫一遍最诚实。下面这段 Python 构造一批示意样本，让便宜模型的置信度与「是否答对」正相关。然后对不同阈值统计升级比例、准确率与总成本。示意里把 Opus 当作全对，数值只做演示，不是复现热帖数据：

```python
"""Threshold scan for a cascade: cheap model first, escalate low-confidence cases.

Illustrative data only. Shows how the threshold moves escalation ratio,
accuracy, and total cost together.
"""
import random

random.seed(7)
N = 100_000
CHEAP_COST = 1.0      # relative cost of one cheap-model call (illustrative)
OPUS_COST = 90.0      # relative cost of one Opus call (illustrative)

samples = []
for _ in range(N):
    conf = random.betavariate(2.0, 3.0)          # confidence in 0~1, mostly low
    ok = random.random() < 0.70 + 0.28 * conf    # higher confidence -> more likely right
    samples.append((conf, ok))

print(f"{'threshold':>9} {'escalation':>10} {'accuracy':>9} {'cost':>10}")
for threshold in [0.20, 0.30, 0.40, 0.50, 0.60, 0.70, 0.80]:
    escalate = 0
    correct = 0
    for conf, ok in samples:
        if conf < threshold:
            escalate += 1
            correct += 1          # escalated cases go to Opus, treated as correct here
        else:
            correct += ok
    cost = (N - escalate) * CHEAP_COST + escalate * OPUS_COST
    print(f"{threshold*100:>9.0f}% {escalate/N*100:>10.0f}% {correct/N*100:>9.2f}% {cost:>10.0f}")
```

跑出来的趋势很清楚：阈值越松，升级比例越低、成本越低，但准确率也一路下滑；阈值越紧，准确率贴向 Opus，成本也重新涨回去。所谓「追平准确率」的结论，永远绑定某个具体阈值，换个阈值就不成立。

## 阈值怎么落地

把原理变成上线动作，顺序大致是三步。第一步，留一块不参与训练的评测集，把阈值从松到紧扫一遍，得到「准确率—成本」曲线。第二步，按业务能接受的最低准确率，取成本最低的那个阈值。第三步，把阈值和评测集一起存档，数据分布变化时重扫。很多人只记得「我们加了级联，省了钱」，却忘了阈值和当时的样本分布是绑定的——这个遗忘，往往是上线后准确率神秘下滑的真正原因。

## 为什么这套打法不适用于生成任务

级联能省钱，有个隐藏前提：任务有客观对错，模型的置信度信号可信。实体消歧这类题答案唯一，便宜模型给出的置信度经过校准后，可以当成可靠的升级依据。生成类任务就不行——写一段文案、编一段代码，「好不好」没有唯一标尺，模型的自我置信度往往过度自信，很难找到可信的「拿不准」刻度。

更麻烦的是，生成任务的「自信」会被采样策略污染：同一个 prompt 换个 temperature，输出的多样性和模型自评的确定性都会变，而这些变化与「答案对不对」没有稳定关系。所以这条省钱路线适合判断题，不适合开放创作题。这个边界，比阈值本身更值得记住。

## 上线前还要算两笔账

第一笔是误判代价。省下的 inference 费用，如果被漏判造成的损失吃掉，优化就是负收益。阈值应该落在「升级比例 × Opus 单价」与「漏判率 × 单次误判代价」的交点附近，而不是拍脑袋定一个。

第二笔是分布漂移。热帖里「准确率持平、成本四分之一」的结论，绑定的是具体任务、具体数据集和具体阈值。换一批分布不同的样本，同一个阈值可能完全不是这个效果。所以阈值要放进评测集里定期回看，而不是一次调好就封存。

## 收尾

便宜模型先判、难例再问 Opus，本质是把「模型选择」从一次性决定，变成按样本动态决策。它没有改变模型本身，只改变钱花在谁身上。在判定类、高通量、错误可定价的场景里，这是当下最划算的优化之一；而写文章、写代码这类生成场景，还是老老实实把 prompt 和评测做好。下次再遇到「全用贵的还是全用便宜的」的二选一，不妨先问一句：能不能让便宜的先答、贵的兜底？
