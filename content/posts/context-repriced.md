一家以「包月自助随便吃」出名的餐厅，某天悄悄把包月自助改成了按盘计价，门口没贴任何告示。老顾客的第一反应通常不是坐下来算账，而是觉得「今天的菜变少了」。DeepSeek 最近调整对话上下文上限，用户侧的体感几乎一模一样：长文档读不动了、长代码会话处理方式和昨天不同，于是第一直觉是「它今天变笨了」。

但这件事与其说是能力变化，不如说是一次迟到的定价回归。具体调整前后的上限数字、生效日期和档位差异，素材没有披露，本文不替它编。能讨论的，是这次调整牵出来的三层账：上下文为什么会被重新计价、变更为什么需要被看见、用户又能拿回什么主动权。

## 第一层账：上下文既是计价单位，也是体验承诺

对 LLM 来说，上下文窗口决定一次请求能装下多少历史信息。窗口越大，一次请求吃掉的显存越多、响应越慢，这种开销在低价档位里几乎无法长期扛住。窗口里每多一个 Token，都要多占一份显存和一份排队时间，这些成本最终都会回到价格上。更麻烦的是，这个成本不是线性的：把窗口翻倍，代价往往不止翻倍，因为模型要同时照顾的信息面更宽了。换句话说，低价档位里的长上下文，本质是一种补贴品——用低价的钱，买高端才撑得起的能力。

调整，就是把这笔补贴慢慢收回去。这不是「变笨」，而是价格重新向成本靠拢。用生活化的说法：会议室从三十人改成二十人，房间没变差，只是能坐的人少了。天天开十人小会的团队毫无感觉；依赖三十人大会的团队，才会觉得处处受限。而那些就是冲着长窗口来的人，当初选中它也正是因为这一点——长文档能整段放进去、长代码能一次读完，这正是它和别家拉开差距的地方。如今窗口收了，这份选择的价签自然变了。

## 第二层账：参数改了，通知与降级策略去哪了

讨论里真正的分歧，不在「该不该调」，而在「调之前有没有说」。参数一旦改动却不写进更新说明，用户只会把变化读成「它变笨了」。一段代码昨天还能整段读进去，今天只能读一半，用户不会想到是窗口参数变了，只会觉得模型退步。同一个结果，有告知是产品调整，没告知就是信任损耗。

一个及格的变更告知，至少要回答三件事：改了什么、为什么改、超限之后怎么办。老会话里已经堆了很久的上下文，是自动截断还是提示迁移？截断的时候，是保开头还是保结尾，用户有没有得选？超长文档有没有替代路径，比如分段上传、临时扩窗或者导出归档？这些降级策略素材同样没有披露，但它才是体感的分水岭：同样收紧上限，有替代路径的是「调整」，没有的是「劝退」。

企业用户有合同和客服兜底，个人用户只能靠产品自己把话说清楚。厂商选择沉默，也许是想避免恐慌，但沉默本身也是一种沟通：用户会用最坏的解释把空白填满。

## 第三层账：用户侧的四条自查与适配

既然窗口参数不由用户决定，能调整的就只剩用法。四条做法，成本都很低。

第一，长任务分层交付。别指望一次把整本手册塞进对话，把大任务拆成小段，一段一段推进，每段的结论单独存档。下次接着做时，把存档结论贴回去当起点，而不是重新读一遍全文。

第二，关键材料放开头。对话越长，靠前的信息越容易被后续内容稀释，把最重要的事实、约束和目标放在最前面，其余资料随用随取。宁可多花一分钟整理开头，也别让模型在几百行之后才看见你的真实需求。

第三，按会话类型选档位。闲聊、问答这类短会话用默认档位；长文档精读、跨文件代码审查这类重活，单独开 Agent 会话、清空干扰，并优先考虑支持长窗口的档位或工具。会话一旦混用，长任务的上下文很快就会被琐碎对话挤占。

第四，把「今天它变笨了」变成可复现的对照。同一份输入、同一套提示词，今天和昨天各跑一遍，记录输出差异，而不是凭感觉下结论。下面这个十几行的 Python 函数，就是分层交付的最小版本：

```python
def split_long_text(text: str, chunk_size: int = 2000) -> list[str]:
    """按字符数把长文本切成多段，长会话分层交付的第一步。"""
    return [text[i:i + chunk_size] for i in range(0, len(text), chunk_size)]

if __name__ == "__main__":
    doc = "长文档内容" * 1500
    parts = split_long_text(doc, chunk_size=2000)
    print(f"总长 {len(doc)} 字符，切成 {len(parts)} 段，首段 {len(parts[0])} 字符")
    assert len(parts) == 4
```

它做的事情很朴素：把一段 7500 字符的文本切成 4 段，逐段送进对话。分层交付不是玄学，就是把「一次装不下」变成「分几次装」。

## 收尾：别盯着「变没变笨」

上下文上限的调整，拆到底是一场成本与体验的权衡：长上下文在低价档位里属于补贴品，收紧是定价回归，缺的只是提前通知和一套体面的替代路径。用户侧真正能做的，不是给模型贴「聪明」或「变笨」的标签，而是把模糊的体感换成具体的问题：窗口现在多大、超限走什么路径、长任务怎么分层。参数会继续调，账永远要自己算。
