Ask HN 上有个帖子问得很朴素：你现在到底怎么用 AI？钱花在哪些订阅上，买没买同厂的多档套餐或多账号，有没有改走按量 API 或 OpenRouter，跑不跑本地模型，用哪套 harness——也就是包在模型外面、负责读文件、跑命令、管上下文的那层工具，上没上多 agent 编排与 swarm（让一群 agent 分工干活）。最后攒下 155 条回复。

把它当排行榜读，会失望——没有统一答案。当现场记录读，信息量立刻出来：开发者争得最凶的，不是哪个模型更聪明，而是哪套工具链不添乱。

## 一、这份清单其实只问了三件事

155 条回复可以归成三格。第一格是账本：订阅档位、多账号、按量计费，钱怎么花。第二格是算力来源：云端 API、OpenRouter 这类聚合入口，还是自己机器上的本地模型。第三格最要命，是手往哪放——原生 CLI、IDE 插件，还是 OpenCode、Pi、Aider、Muse Code 这类替代 harness。

账本能算清，手感只能试出来。而真正让人换工具的，几乎都落在第三格。

清单里还有个耐人寻味的现象：不少人同时留着两套配置。贵的那套专门跑长任务，便宜的拿来改小 bug；买多个账号，常见的理由是额度按周期重置、一个号撑不到月底。这不是忠诚度问题，而是额度节奏和任务长度对不上时的土办法——工具没变，用法先变形了。

同一时间，知乎上有个问题问得更直接：DeepSeek harness 相比 Codex 差在哪？高赞回答很少谈模型能力，列的全是工程细节——IDE 与编辑器集成的成熟度、工具调用的稳定性与失败重试、长任务里的上下文管理与压缩、社区插件和排错资料的丰富程度。

两组讨论拼在一起，指向同一个结论：日常体感由工程细节决定，而换不换工具，往往跟模型跑分没关系。

## 二、把「留存」拆成四个能看见的指标

「留存」这个词太虚。拆开看，其实就四件事。

**第一，任务中断率。** 模型像发动机，harness 像变速箱。发动机马力再大，换挡一顿一顿，人开两天就想换车。一个 agent 任务跑到第七步，权限弹窗拦住、路径找不到、命令超时，你被迫接手，这单活儿就从「它干」变成「你盯着它干」。

**第二，重试成本。** 工具调用失败后，重试几次、怎么退避、失败信息给不给模型看，这些细节决定了账单。每重试一轮，往往要把文件再读一遍、命令再跑一遍，Token 消耗跟着翻。比钱更贵的是注意力：你得判断它是在重试，还是已经卡死。

**第三，上下文压缩的损失。** 长任务里 context 一定会满，压缩不可避免。这像出差前把行李抽真空：抽得好省一半地方，抽过头把充电器的线压断。被压掉的那条约束——比如「不要动生产配置」——常常到第三步才发作，而那时你已经签收了好几处改动。

**第四，排错时能不能搜到答案。** 报错原文丢进搜索引擎，有没有人踩过同一个坑？插件市场有没有现成补丁？文档里写没写这个参数？这一条最不技术，却最影响去留：一个下午能不能救回来，常常取决于别人有没有替你写好答案。

## 三、领先两个百分点，抵不过一次卡死

这点领先摊到日常工作里，大概就是某天少改一行代码、少问一次「这里为什么报错」。这种收益是渐进的，渐进的东西很难触发迁移——没人会为了每月省五块钱换宽带，但断网一小时，第二天就去营业厅。

痛点是阶跃的。一次工具调用卡死半小时，当天产出直接归零；一次上下文压缩丢掉关键约束，三处配置改错，回头排查又是两小时。收益曲线平缓、损失曲线陡峭，人的决策自然偏向「别再让我踩坑」，而不是「再聪明一点」。

团队层面的账更直白。个人换 harness 只是重装一次软件；团队换，要迁 CI、迁权限、迁几十份脚本文档，还得解释为什么上周能跑的流程这周不能跑。所以团队评估工具时更认下限：能不能稳定交接，比能不能多解一道难题重要得多。

连计费方式也是同一笔账。订阅制（subscription）与按量计费的分野在于：包月像健身房年卡，用得足够多才回本；按量 API 像打车，每一趟都看得见钱；OpenRouter 像换乘站，一个 key 换多家模型。选择越多，工具链的稳定性越容易被摊薄——每多接一层，就多一处可能出错的地方。

更微妙的是成本结构。业内普遍认为，模型推理（inference）的边际成本（marginal cost）仍在往下走，可工具链的维护成本不会跟着降：重试策略要人调，上下文压缩的规则要人写，报错文档要人补。这部分开销不随 Token 降价而消失，反而随着用法变复杂而上涨。

## 四、三个问题，比榜单好用

所以评估一套 AI 工作流，不妨换三个问题，都跟你自己有关。

你今天被打断了几次？打断之后，要不要从头把背景再讲一遍？出问题时，十分钟内能不能搜到答案？

三个问题都指向同一个东西：下限。模型榜单衡量的是上限——最好情况下它能做到多好；而工作流决定的是下限——最差情况下它会不会把你拖下水。决定你明天还打不打开它的，从来是下限。

155 条回复没有给出标准答案，但它给出了一个更实际的判断方式：别问哪个模型最强，先问哪套工具让你少救几次火。工具是每天要开的车，不是每年看一次的跑分表。
