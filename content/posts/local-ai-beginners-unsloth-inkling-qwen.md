你家里那台平时只用来打游戏、偶尔跑跑视频剪辑的显卡，可能正躺着一块能顶替「云端订阅」的算力。

这两年用云端 LLM 的人多少都有点疲惫：用量一到上限就开始倒计时，价格说涨就涨，更让人无语的是「最新版」偶尔还不如上一版好用。于是有人动了念头——不如干脆自己搭一套，装在自己家的 Windows 电脑上，不盯着用量条，也不用月月续费。今天这篇文章，就带你看看这条路能走多远，以及它的分界线到底划在哪。

先说结论：分界线不在软件步骤上。装软件、下模型、设参数，加起来三步，熟练了十分钟出头。真正决定你能「搬回多少 AI」的，是你的显卡显存（VRAM）有多大，以及你愿意为「放得下」牺牲多少精度。

## 三个前提，缺一不可

想在自家跑本地大模型，需要三样东西。

第一，一台带独立显卡的 Windows 电脑。显存越大，能跑的模型越大。作者自己用的是 RTX 5090，32GB 显存，属于消费级里的天花板。

第二，一个叫 Unsloth Desktop 的软件。它免费、开源，Windows、macOS、Linux 都能装，专门跑 GGUF 和 MLX 这两种格式的量化模型，把一堆终端命令和 Python 环境打包进一个图形界面。同类的还有 LM Studio。

第三，一个按你显存大小挑好的量化模型。这是关键，也是后面所有取舍的起点。

## 三步，把模型请回家

第一步，装 Unsloth Desktop。双击安装包，点完下一步就行，全程没有命令行。

第二步，在模型下拉框里挑一个量化版本。作者选的是 Qwen3.8-27B 的 UD-Q4_K_XL 这个版本，文件大约 18GB。

第三步，点模型旁边的齿轮，设置 context size。作者设的是 128K，也就是模型一次能「记住」多少对话内容的长度。

到此为止，你的第一个本地 AI 就能在软件里直接聊天了。如果想让全家一起用，还可以再开一步：在设置里设一个 Remote password，然后启动 LAN access，家人用浏览器输入软件给的地址，用户名填 `unsloth`、密码填你刚设的那个，就能在网页里聊天。前提是那台电脑得一直开着、Unsloth 一直运行。

## 显存就是「工作台面积」

为什么同样的软件，别人跑 27B 模型，你只能跑 9B？答案是显存。

你可以把显存想象成一张工作台。模型越大，摊开的「图纸」就越大，占的工作台面积越多。台面只有那么大，图纸太大就放不下。8–12GB 的显存，只能放下 9B–12B 的小模型，比如 Qwen3.5-9B、Gemma 4 12B；16GB 能上到 Qwen3-14B、gpt-oss-20b 这些；24GB 能跑 Gemma 4 31B、Qwen3.8-27B；32GB 以上，才能舒舒服服跑 Qwen3.8-27B 和 Inkling 2 Mini，还能留出大量空间给长对话。

全尺寸的 Qwen3.8-27B，16-bit 权重就有约 56GB，消费级显卡根本装不下。想把它塞进几十 GB 的显存，只能靠「量化」。

## 量化：把高清照片压成压缩包

量化，就是把模型的权重压到更低的精度，换来「放得下显存」和「跑得更快」，代价是精度。

这个比喻很直观：同一张照片，存成 8-bit、4-bit、2-bit，颜色细节会一层层丢失，最后变成糊成一团的大色块。模型权重也一样，从 Q8 到 Q4 再到 Q2，细节逐级丢。区别在于，有的任务对精度几乎无感，压过之后输出照样能看；有的任务则近乎不可用，压得越狠，质量崩得越快。

所以量化不是「免费的午餐」，而是一道选择题：你愿意为了让它跑起来，让出多少质量？

## MoE：只请需要的那几位专家上桌

表格里有个细节值得停下来看：16GB 那一档里，居然出现了 30B、35B 的模型，比如 Qwen3-Coder-30B、Qwen3.6-35B。35B 的模型怎么塞进 16GB 的卡？

答案在「MoE」这个词上，全称 mixture of experts，混合专家。普通模型每个 token 都要动用全部参数；MoE 模型则把参数分成一堆「专家」，每个 token 只激活其中几十亿参数，其余的就放在系统内存里候着。打个比方：普通模型是「一屋子人全站起来干活」，MoE 是「只把需要的那几位专家请上桌，其他人先歇着」。

所以一个 35B 的 MoE 模型，真正跑起来的激活参数可能只有几 B，自然能塞进小显存。作者举例，在 RTX 5060 Ti 16GB 上，Qwen3.6-35B 能跑到约 47 tokens/秒，这个速度日常完全够用。当然，没被激活的参数放在系统内存里，速度会稍慢一点。

## Inkling 2 Mini 为什么值得试

聊到本地模型，绕不开一个新鲜名字：Inkling 2 Mini。

它是 Thinking Machines Lab 在 2026 年 11 月 17 日发布的模型，26.4B 参数，Apache 2.0 开源，支持视觉输入，还有 1M token 的超长 context。Unsloth 推荐的 UD-Q4_K_XL 文件是 17.6GB，跟前面 Qwen3.8-27B 的约 18GB 几乎同量级，32GB 的卡放进去，还能留约 14GB 给 context。

它同样是 MoE，激活参数只有 5.4B，所以 4-bit 版本甚至能在 16GB 的卡上跑，剩下的部分放系统内存、稍慢一点。按 Unsloth 的口径（RAM 加 VRAM 合计、只算模型本体），它的内存占用大致是：2-bit 约 10–11GB（12GB 卡能全放）、3-bit 约 13–15GB（16GB 卡）、4-bit 约 17–18GB（24GB 卡推荐）、8-bit 约 24GB（32GB 卡）。

不过别被「Mini」骗了——它的兄弟 Inkling 2 Small 名字里带个「小」，实际却是 594B 参数的庞然大物，Unsloth 最小的文件也要 171.7GB，那已经是 256GB Mac Studio 或 DGX Station 这种统一内存机器的领域，不是普通显卡能碰的。

## 一段小代码，帮你算「放不放得下」

想快速估算一个量化模型大概占多少显存，不用装任何第三方库，几行标准库就能算。下面这个例子按「参数量 × 每个权重的位数」粗估体积，再按你的显存预算给个起步建议：

```python
# -*- coding: utf-8 -*-
"""纯标准库示例：按量化精度估算模型体积 + 按 VRAM 预算选档位。"""


def est_size_gb(params_b: float, bits: int) -> float:
    """按「参数量(十亿) × 每权重位数」粗估模型本体体积(GB)。

    1 byte = 8 bit，所以参数(B) × bits / 8 = 字节，再换算成 GB。
    """
    return params_b * 1e9 * bits / 8 / 1e9


def pick_tier(vram_gb: float) -> str:
    """按 VRAM 预算给一个起步档位建议（仅粗估，真实占用看工具内 calculator）。"""
    if vram_gb < 8:
        return "显存太小，跑本地模型会很勉强"
    if vram_gb < 16:
        return "Small：Qwen3.5-9B / Gemma 4 12B（8-16K context）"
    if vram_gb < 24:
        return "Medium：Qwen3-14B / Qwen3.6-35B(MoE) / Inkling 2 Mini（16-32K）"
    if vram_gb < 32:
        return "Large：Gemma 4 31B / Qwen3.8-27B / Inkling 2 Mini（16-32K）"
    return "Extra Large：Qwen3.8-27B / Inkling 2 Mini（64-128K+）"


if __name__ == "__main__":
    for bits in (8, 4, 3, 2):
        print(f"Inkling 2 Mini @ {bits}-bit ≈ {est_size_gb(26.4, bits):.1f} GB")
    for card in (12, 16, 24, 32):
        print(f"{card} GB 显存 → {pick_tier(card)}")
```

跑出来大概是：26.4B 的模型，4-bit 约 13.2GB，8-bit 约 26.4GB。需要强调，这只是个粗略估算，只算了模型本体，没算 context 占用的显存；真实能不能放下，还是要以工具里的 VRAM calculator 为准。

## LAN 共享的边界：只限家里

这套方案有个明确的边界——它只在家庭局域网内可用。

所谓 LAN 共享，就是让同一台路由器下的家人，用浏览器连到你这台电脑上跑模型。它不能直接跨互联网访问，你在公司、在路上是连不回来的。这也意味着它更适合「一家人共用一台常开的电脑」的场景，而不是「随时随地访问自己服务器」的需求。

## 什么时候本地其实不划算

别急着把订阅全退了。本地 AI 不是万能答案，有几个场景它明显吃亏。

一是你只是偶尔用。为了一周几次的对话，专门常开一台电脑、占着一块显卡，电费和麻烦程度可能比订阅还高。二是你确实需要顶级大模型。本地能跑的，终究是量化过、压过精度的「缩水版」，真遇到需要 56GB 全尺寸权重才能胜任的重活，消费级显卡还是力不从心。三是你要联网、要实时信息。本地模型跑在你自己机器上，默认不接外部搜索，需要额外搭 agent、配工具，这又是另一摊事。

所以结论不是「本地全面取代云端」，而是「把那些 token-heavy、重复性高、又不敏感的任务搬回家」——而云端，留给那些偶尔的、需要大模型或联网的活。分界线，始终画在显存大小和你对精度的容忍度之间。
