让 agent 替你上网办事，有两副面孔。一副像临时工：你交代一句，它打开浏览器，东点一下、西看两眼，边试边改；另一副像老师傅：第一次多花功夫把路线摸清、写成操作手册，往后每次照手册走，又快又稳。YC F26 团队 Pomerado 最近发布的自助平台，做的就是后一件事。你先用人话把任务说清楚，agent 实打实跑一遍，把走通的路径固化下来，交付出一条可以反复调用的 MCP 服务。官方给出的账本很直接：首次交付约一小时，之后每次调用通常 5 到 30 秒，比「让 agent 现点网页」快大约一个数量级。

## 先跑一遍，再冻起来

Pomerado 的流程可以拆成三步。第一步是录制：agent 按你的描述，实际走一遍目标流程——该发 HTTP 请求就写请求，该操作页面就写 Playwright 脚本，把导航和交互路径摸清楚。第二步是固化：把这段跑通过的路径，转成一条确定性 MCP，输入输出都固定下来。第三步是复用：以后每次调用直接走这条固定路径，不再重新探索。

这里最关键的词是「确定性」。让 agent 现点网页，等于每次都重新探索：页面结构、按钮位置、表单字段，它都要重新看一遍，又慢又带随机性。固化之后，探索只发生一次，剩下的都是程序执行。这个道理很像第一次去陌生的办事大厅：问路、找窗口、摸流程，花上一个小时不冤；把这套流程写成一张带地图的指引，往后每次进门直奔窗口，几分钟办完。第一次的慢，是在替后面所有次买速度。

如果把现点网页比作每次出门都现打车，那 Pomerado 的路子更像是在家和公司之间修了一条专用小轨道：修轨道要一次性投入，之后每趟又快又便宜。区别在于，打车能去任何地方，轨道只能走固定路线。这正是「探索」与「固化」的取舍：拿灵活性换速度。

## 什么样的任务值得固化

放到成本结构里看，这是一次搬迁：把「每次都要付的探索成本」，前置成「一次性付出的固化成本」。什么样的任务值得搬？特征很朴素——跑得足够频繁，步骤相对固定。一小时的前置投入，会被几十次、几百次调用迅速摊薄。反过来，一次性探索就不值得：比如「帮我随便看看这个网站长什么样」，任务还没等你固化就已经结束，那个小时等于白花。

还可以再加一条：页面本身要够稳定。一个三天两头改版的后台，你上周固化的路径这周可能就失效，摊薄期还没到，维护账单先到了。真正划算的，是那些界面几年不动、你却每周都要进去操作几十次的场景——报账、查库存、发周报，越无聊，越适合交给固化后的程序。

## 维护，比想象中更贵

但确定性不是免费的午餐。网页会改版，接口会变，字段会挪位置。固化出来的 MCP 像一条水泥路，走起来快，可路面一旦开裂就得修。Pomerado 的应对是：运行失败时自动触发维护任务，把坏掉的步骤修好。这听起来优雅，其实只是把问题挪了一层——从「谁来点网页」变成「谁来保证自动修复没有把路修歪」。一台会自己修路的机器，仍然需要一个人去验收它修出来的路。这层「维护的维护」，是这条路线最容易被人忽略的新成本。

再往深想一步，自动修复本身也需要被信任。维护任务同样是由模型生成的改动，它也可能改错字段、删掉步骤，或者在「修好」的同时埋进新的问题。于是链条变成了：agent 跑流程，失败，自动修复，谁来检查修复？若检查也交给模型，那只是把人工验收往后推了一层，而不是取消它。这个位置，正是这类工具未来最值得被盯住的地方。

## 给确定性上四道保险

防错方面，Pomerado 做了四件事，值得单独说。第一，调用过护栏：一个独立的 Guardian 模型按预设规则审查 agent 发出的调用，不让它乱打。第二，测试用合成输入：故意造一批变体输入来跑，避免接口只对录制时那一个样本过拟合。第三，发布前校验 schema：由另一个 agent 检查输入输出结构，保证交付出去的接口是规整的。第四，凭据隔离：需要登录和两步验证的站点走确定性登录流程，模型和录制器都接触不到用户凭据。这四件事合起来，是在给「确定性」上保险——路径确定还不够，还得保证这条路径不越界、不偷懒、不泄密。

## 边界：高频与低频

项目现在给出 MIT 开源代码，也提供免费托管版。它的定位很清楚：不是又多了一个 MCP 工具，而是把「探索型 agent」和「确定性程序」之间的分界线，做成一个产品。适合它的任务画像：高频、重复、流程稳定；不适合的画像：低频、一次性、页面三天两头改。判断标准可以很朴素——这个任务你下周还会不会原样再做一遍？会，就值得花一小时把它固化；不会，就随 agent 慢慢点。

换句话说，探索型 agent 把不确定性留在运行时，而确定性 MCP 把不确定性搬到了维护期。省下的不是工作量，只是把成本换了个记账科目。看清楚这笔账的人，才知道哪些任务该固化，哪些该让 agent 继续现点。Pomerado 真正展示的，是 agent 时代一种务实的工程选择：把贵而慢的智能，用在第一次探索上；把便宜而快的确定性，留给之后的每一次执行。代价是维护，以及维护本身的审核。谁来验收自动修好的步骤，谁就是这套新成本结构里最后一道、也最贵的一道关卡。
