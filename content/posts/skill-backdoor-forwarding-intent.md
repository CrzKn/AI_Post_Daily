title: "你把「想要什么」交给了 agent，却没看见它把这句话转发给了谁"
date: 2026-11-28T11:04:00+08:00
tags: ["ai-security", "agent"]

很多人现在写代码的动作是这样的：不打开编辑器，先打开对话窗口，敲一句「帮我做个记账小程序，能分月份统计，还能导出 Excel」。回车之后，agent 替你拆需求、搭目录、写代码，你只管在它停下来时看一眼，说声「继续」。

你有没有想过，这句话接下来去了哪儿？它进了模型，可能也进了某个你从没听过的 skill，而这个 skill 可能顺手把它转发给了另一台服务器。这件事听起来像阴谋论，但它已经被真实发生过的事件摆到台面上了。有人在 Convex 官方的后端 skill 仓库里提交 issue，指出它的 quickstart skill 会把用户描述的应用想法发到 convex.site 这台主机上，再执行一段远程脚本。而那段代码的写法，是刻意绕过了安全检查的。

要说清这件事为什么值得警惕，得先换个坐标系。过去我们防供应链风险，防的是「代码」。你从 npm 装一个包，怕的是里面混进挖矿脚本、后门、偷 token 的木马。但代码有个好处：它看得见。你可以打开 node_modules，可以 diff，可以搜关键字，可以用工具扫。就算藏得再深，它终究是写死的文本，总有办法把它翻出来。

新的威胁不在这个层面，它换到了「意图」这一层。你交给 agent 的不是一段代码，而是一段自然语言的需求描述。这段文字里往往装着你的产品构想、你的业务逻辑、你的内部数据字段——可能是一个还没公开的功能，可能是一个正在设计中的收费模式。

而这段文字，比代码更难防，因为它不是代码。diff 工具检查代码，检查不了「我想要什么」。你的需求文本一旦被 skill 悄悄转发出去，它去了哪、被谁存下来、又被拿去干了什么，你在本地一个字都看不到。

把 agent 的供应链画成一条链，盲区就清清楚楚。这条链是：模型 → skill 或 plugin → 远程主机 → 执行脚本。你真正「看得见」的，只有自己敲进去的那句话，和 agent 最后回给你的结果。

中间每一跳都是黑箱：模型把你的话消化成了什么，你不知道；skill 收到了哪些字段、又往哪个域名发了什么请求，你不知道；远程主机上那段脚本到底做了几件事，你更不知道。链条越长，你的视野就越短，而麻烦恰恰喜欢藏在你视野消失的那一段。

这件事的吊诡之处在于：泄露发生得比实现更早。代码泄露，通常是项目已经写得七七八八，源码被谁偷了去；意图泄露，发生在你连一行代码都还没写的时候。一个还停留在脑子里的构想，就已经可能躺在别人的服务器上了。等你真的把它做出来，再想追「它怎么泄露的」，连起点都找不到。

再把镜头拉远一点，这件事就不只是写代码的人的事了。同一周的另一条新闻里，模特七海公开说，自己的脸已经被 AI 短剧拿去生成了「赛博恶役」一类的角色。她想维权，却撞上一堵墙：取证难，你不知道是哪家模型、哪个账号生成的；定位主体难，背后可能是一串皮包工作室，告谁都不知道。

平台下架之后，换个账号、换个剧名，同样的脸几小时后就重新上线。这条链的本质，和 skill 转发需求一模一样——只不过被转发的主体，从一段文字换成了一张脸。

两条线合在一起，指向同一个结论：事后追责这条路，已经跑不赢生成的速度了。「发现—取证—定位主体—下架」这套老流程，每一步都要人力和时间，而对方生成一个变体只需要几秒钟和近乎零的边际成本。等你在第一件侵权上走完流程，对方已经生成了第一百件。真正还来得及的防线，只剩两样：事前授权，和可追溯的来源标识——比如 C2PA 这种内容凭证，让每一段生成内容都带着「谁、用什么、什么时候」的底账。

落到具体操作，有三条自保法是当下就能做的。第一，装任何 skill 或 plugin 之前，别只看它的 README 写得有多好，要看它实际会发出哪些网络请求：outbound 到哪些域名、会拉取或上传什么、有没有夹带一段没说明用途的远程脚本。审查它的真实行为，而不是它对自己的描述。

第二，把「需求描述」当成敏感数据来对待。别把内部字段、未公开的构想随手贴进 prompt，就像你不会把公司内部文档随手发到陌生人的群里。第三，给 agent 的执行环境做最小出站：白名单、隔离环境，不默认允许它任意外联。它需要联网才能干活，和你允许它联网到任何地方，是两回事。

这里必须说句公道话：问题从来不在「联网」本身。很多 skill 确实需要连网才有用，远程调用也不是原罪。真正错的是三件事叠加——它没告诉你，它绕过了检查，而且它把你最不该外传的那部分，当成了可以顺手转发的东西。一个有诚意的 skill，应该把「我会把这些信息发到哪里、为什么」写在明处，让你在同意之前就看见。

说到底，这事的本质是信任边界的位移。软件时代，信任的对象是「代码」，你担心它做什么坏事，可以查。agent 时代，信任的对象悄悄变成了「意图」，你担心它把你的想法送到哪去，却无处可查。而所有事后补救的机制，都是为「看得见的代码」设计的，还没跟上「看不见的意图」。所以能救场的，只有把防线往前推：装之前先审行为，用之前先想清楚你交出去的是不是敏感信息，以及让每一段从你手里流出去的东西，都带上来源、带上授权、带上一本能查的账。
